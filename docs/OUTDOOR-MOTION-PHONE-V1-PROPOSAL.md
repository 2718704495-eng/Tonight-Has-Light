# OUTDOOR-MOTION-PHONE-V1 手机可读微风提案

> 日期：2026-08-25；2026-08-26 用户批准 A  
> 负责人：主任务窗口  
> 当前状态：`A APPROVED / LOCAL IMPLEMENTATION AUTHORIZED / NO UPLOAD / NO RELEASE`  
> 触发证据：用户在微信真机体验 `0.4.3` 后反馈“风声有，但画面不会动”

批准记录：[`OUTDOOR-MOTION-PHONE-V1-A-APPROVAL`](./OUTDOOR-MOTION-PHONE-V1-A-APPROVAL.md)；获批提案 SHA-256 `728a11c90604d2728ed777806b4d6b766cfb06fe3877c036a590639564d29249`。

## 1. 现状与根因

`0.4.3` 的视觉时钟与图层参数在本地 390×844 运行时持续更新，因此不是 Cocos 或微信小游戏天然无法播放动画。问题是动效在手机正常倍率下不可读：

- 开场风链只覆盖约 `0.7–4.75s`；用户首次触碰并听到风声时，开场可见风可能已经结束。
- 正式持久调度在 `20s` 后再等待 `8–18s`，当前确定性种子下第一阵循环风约在 `32.18s` 才开始。
- 已批准 B-lite 的草／发梢／衣角／猫耳／尾尖峰值约为 `1.5°–4.8°`，人物和猫的呼吸缩放约为 `0.4% / 0.3%`；本地逐帧差分存在，但全屏 PSNR 多数约 `59–86dB`，肉眼接近静态。
- 既有 r3 Web smoke 只证明户外挂载和主流程可走，返回户外证据约在 `83ms` 采集，没有覆盖 10–35 秒正常倍率可见性。

因此 `0.4.3` 的手机动效判定为 `FAIL / P1`，不得继续发布；这不是用户观察问题。

## 2. 研究结论

- Apple 的 Motion 指南强调：动效应有明确目的、帮助界面与游戏“活起来”，同时不能妨碍使用，并应尊重 Reduce Motion。  
  <https://developer.apple.com/design/human-interface-guidelines/motion>
- Apple 的 Accessibility 指南要求尊重减少动态设置，避免持续、强烈或会造成不适的运动。  
  <https://developer.apple.com/design/human-interface-guidelines/accessibility>
- WCAG 2.2 允许用户关闭由交互触发、且非功能必需的动态。  
  <https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html>

本项目因此不应把画面做成大幅飘动，也不能把“克制”做成“看不见”。手机正常倍率要能读出一次风从草传到人和猫；减少动态模式继续保持静态等价。

## 3. 保持不变项

两个方案都严格保持以下已批准内容：

- V7 的角色、构图、材质、配色、单条淡银河、星空结构、门光、两朵花及室内暖屋样式。
- 风的方向和因果顺序：远草→近草→人物发梢／衣角→猫耳／尾尖。
- 首触前数字静音；首触后环境风先响应，音乐仍未批准、不接入。
- 不新增粒子、Bloom、3D 灯光、按钮、教程、任务提示或镜头推进。
- 减少动态模式中 transform、草浪、云位移和视差为 `0`，只允许不超过 `200ms` 的亮度／交叉淡化。

## 4. A／B 方案

### A：可感知微风（负责人推荐）

目标：用户在手机上进入后数秒内能看到画面在呼吸；首次触碰听见风时，画面也同步出现一阵轻风。

1. 首次触碰时触发一条完整视觉风链；若当时已有风链在运行，则不叠加。
2. 开场或首触风结束后 `8–12s` 内出现下一阵风；后续每 `9–14s` 非固定出现一次，避免机械循环和二三十秒静止空窗。
3. 只调整现有六个局部通道和呼吸幅度，不改资产、节点、枢轴、方向或先后顺序：

| 通道 | 当前峰值 | A 候选峰值 |
|---|---:|---:|
| 远草 | 1.5° | 2.2° |
| 近草 | 2.5° | 3.6° |
| 人物发梢 | 2.5° | 3.8° |
| 人物衣角 | 3.0° | 4.2° |
| 猫耳 | 3.0° | 4.5° |
| 猫尾尖 | 4.8° | 6.5° |
| 人物呼吸 | 0.4% | 0.6% |
| 猫呼吸 | 0.3% | 0.7% |

4. 局部 overlay 上限只做同方向的小幅增强，最高不超过 `0.40`；门、银河和花不增强，不制造闪烁或任务焦点。

优点：能同时解决“听见风却看不见风”和长空窗问题。  
风险：签名动效可见度提高，需要重新做正常倍率、缩略图与低亮审查；因此必须获得用户批准后才能实现。

### B：保守同步

1. 保持 B-lite 所有幅度不变。
2. 仅在首次触碰时重播现有风链，并把下一阵风改为 `8–12s` 内出现。

优点：样式变化最小。  
风险：现有幅度已被真机反馈和逐帧量化证明过弱，仍可能被读成静态，因此不推荐。

## 5. 实现与验收边界

用户批准后才允许：

1. 以新候选 ID 实现，不修改或冒充已上传 `0.4.3`。
2. 生成 390×844 的 35 秒正常倍率视频，覆盖开场、首触同步风和至少一次后续阵风；记录触摸与每段峰值时间。
3. 补 360×800、390×844、430×932 截图和减少动态视频。
4. 正常倍率下，独立观察者能无标注辨认“草先动→人物衣发→猫耳／尾尖”，并确认门、星空和两朵花未抢焦。
5. 验证首触风不与自动风叠加，35 秒内不存在超过 14 秒的可见风空窗；输入 P95≤100ms，无 >250ms 冻结；中高端平均保持 55–60fps，低端降级后稳定不低于 30fps。
6. 只有通过本地和独立 QA 后，才另行向用户申请微信开发版本构建／上传授权；不提审、不发布。
