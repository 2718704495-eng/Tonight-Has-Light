## 1. 这轮解决什么

D-lite V3 已把“户外 → 点门 → 室内 N01 → 收尾／分享”的主功能接通，但旧室内 `TonightHasLightV0View` 仍是本地 Graphics 功能壳，不能成为正式画面。本轮先冻结用户真正看见的空间、UI、门转场、杯子小剧场与分享承载方式；用户批准前不修改 Cocos 运行时样式。

户外 V7、成年人＋普通家猫、B-lite 风链、两朵弱光花、门光层级与已批准风声全部保持不变。V7 和本轮生成图都只是方向／构图参考，不是正式入包资产。

## 2. 研究怎样影响设计

- 自然场景常被评价为更具恢复感，但研究并未证明它会稳定提升所有认知表现。因此产品只表达“陪你慢下来”，不作治疗、助眠或情绪改善承诺。[自然场景研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC9084315/)
- 夜间低照度在特定实验中更舒适，但色温效应并不一致。因此室内采用“大面积低亮冷蓝＋一小块暖壶光”，不把某一种色温包装成普适心理处方。[晚间照明研究一](https://pmc.ncbi.nlm.nih.gov/articles/PMC7843969/) · [晚间照明研究二](https://pmc.ncbi.nlm.nih.gov/articles/PMC7984641/)
- 交互引发的非必要位移必须允许关闭；正文与背景仍按 4.5:1、关键图形按 3:1 检查。[WCAG 动画](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions) · [WCAG 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)
- 暖光拖拽必须有“先点暖光、再点水壶”的等价路径，不能只靠精细拖动。[WCAG 拖动替代](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)
- 微信右上胶囊和异形屏不能靠固定空白猜测；正式 Cocos 版使用 SafeArea／运行时 inset，并把安静设置入口放在左上安全区。[Cocos Creator 3.8 SafeArea](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/editor/safearea.html)

这些证据只支持设计约束，不构成医学结论或体验效果验收；“舒服、愿意多坐一会儿”仍需后续真人开放题验证。

## 3. 两个可见方向

| 方向 | 核心构图 | 优点 | 主要风险 | 资源估算 | 负责人结论 |
|---|---|---|---|---|---|
| `INDOOR-N01-A-V1` 窗边小桌 | 窗在左，人物左下、猫右下，矮桌与水壶偏右；原创木臂纸罩灯只投一块可移动暖光 | “窗外冷夜 → 人物与猫 → 壶边暖光”层级最稳；核心互动清楚；减动与多尺寸成本较低 | 窗外星河若过亮会抢水壶；纸灯必须原创重绘，避免像知名灯具 | 约 32–36 个可动／静态层，2 张场景图集＋1 张 UI/字体图集 | **推荐** |
| `INDOOR-N01-B-V1` 半开门廊 | 左侧门框保留户外，室内矮桌靠中，人物与猫坐在前景 | 户外到室内连续感最强；“风停在门边”容易理解 | 门容易再次像关卡入口；前景、透视与外景争焦；适配复杂 | 约 40–46 层，成本比 A 高约 25%–35% | 备选 |

内部启发式评分（不是用户研究结果）：A 为 88/100，B 为 75/100。评分权重为情绪连续 25、核心互动清楚 25、安静层级 20、多尺寸／无障碍 15、资源成本 15。

## 4. 推荐 A 的完整首夜可见链

1. 用户在 V7 户外主动触门。
2. 门光在 120ms 内只回应一次；暖色染纸边扩张约 680ms；同色灯池在约 120ms 内显出室内。总长约 0.9s，不推镜头、不放大角色。减少动态时改为 180ms 交叉淡化。
3. 进入室内后出现竖排 3/5/8 分钟选择，默认 5 分钟，但用户必须确认；不显示倒计时。
4. 前 10 秒让用户看房间；随后只出现“把这点光，带到壶边。”暖光可拖，也可点暖光再点水壶，吸附宽松、没有失败。
5. 人物疲惫地把杯子倒扣；普通家猫只闻一下并用前爪轻碰一次；人物停 0.8s 后自己翻正。猫不拟人、不替用户完成核心任务。
6. 收尾只将房间压暗约 4%，显示“水热了。你也先缓一会儿。”并提供“再坐一会儿／今晚到这里”。
7. 分享前先出现应用内预览，固定文案为“有人给你留了一盏灯”；外部卡按 500×400 生产，不含姓名、头像、留言或进度。

声音承接提案：触门不用通关提示，只给一次很轻的木门／纸灯触感；0–0.9s 将已批准风声柔和收窄，进屋后交给很低的壶鸣与房间底噪。音乐方向仍由 `GC-MUSIC-DIRECTION-V1` 单独等待批准，本提案不批准或接入音乐。

## 5. 建议一起冻结的产品分叉

| 分叉 | V1 建议 | 理由 | 当前状态 |
|---|---|---|---|
| 室内方向 | A“窗边小桌” | 核心仪式最清楚，适配和减动成本最低 | `BLOCKED` |
| 户外设置入口 | 用户首次触碰后在左上安全区出现；若零操作，则 20 秒后出现 | 保留 0–20 秒零 UI 赏景，同时让主动用户及时找到声音／减动 | `BLOCKED` |
| 房间亮度 | V1 暂不提供应用内亮度滑杆 | 当前 LocalSaveV2 无该字段，且会干扰设备亮度与暗部验收 | `BLOCKED` |
| 后台返回 | 室内停在最近安全节点，显示“我们停在这里了。”；用户选继续或结束 | 防止声音、微剧场或计时越权恢复 | `BLOCKED` |
| 擦窗雾结果 | 露出稀疏星群，不新增满月 | 延续户外夜空，避免第二个强焦点 | `BLOCKED` |
| 字体 | 功能字用思源黑体子集，两句叙事用思源宋体子集 | 可读性和日记感分工明确；需登记 SIL OFL | `BLOCKED` |

## 6. 正式资产与 Cocos 边界

- 两张 imagegen 图只用于光色、构图与材质探索。正式人物、猫、窗、灯、壶、杯、文字、Logo、功能图标与关键互动全部原创分层重绘并登记作者、来源、许可、人工修改版本和 SHA-256。
- 室内使用持久 Scene／Prefab／Sprite／离线 Atlas；不扩展旧 Graphics 壳，不做整屏销毁重建，不依赖小游戏默认关闭的动态合图。
- 预估层：房间底、墙／地板、窗框、玻璃／雾、窗外夜空、桌、壶／蒸汽、两个杯、纸灯／木臂、暖光遮罩、人物约 6–8 层、猫约 5–6 层、前景遮挡与 UI。
- 安静观察时不显示 HUD。热区至少 44×44，相邻边缘至少 8px；大字为真实 120%，不使用 SHRINK/CLAMP 把文字挤回原盒。
- 减少动态关闭位移、视差、镜头推进和角色／物件摆动，只保留不超过 200ms 的亮度或交叉淡化等价反馈。
