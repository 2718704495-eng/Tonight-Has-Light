# GATE-C-WIND-A-20260824：夜风样片的局部风链、环境风与证据闭环

## 一句话结论

Wind A 候选已经正确接入真实环境风、修好 430×932 安全边并保持 V7 静态画面零差，但独立 QA 仍看不清猫耳/尾尖的末段风响应，所以本轮工程结果已验证，Gate C 仍是 `FAIL / BLOCKED`。

## 1. 先讲业务：这次到底做了什么

- 谁会遇到这个场景：下班后打开《今夜有灯》、在草坡上安静看夜空的用户。
- 他想做什么：零操作也能感到一阵风从草坡传到人物和猫，首次触碰后听到自然环境风。
- 原来是什么情况：旧候选的风链虽然代码数值正确，但正常倍率下难以看见；环境风还没有与当前视觉候选形成同一证据链；430×932 最外缘有亚像素混色。
- 现在是什么情况：Wind A、真实环境风与适配修正已经进入一个唯一候选，V7 静态样式没有改变；环境风与外缘问题通过独立 QA。
- 为什么要改：用户能看见和听见的体验才是目标，时间轴存在、自动测试通过或差分图有变化都不等于体验成立。
- 验收结果：GC-01/02/04/05/07/08/10/13 通过；GC-06 因人物局部和猫耳/尾尖仍不够可读而失败；真人、音乐、微信真机、低亮和 10 分钟内存继续阻塞，不能进入 Gate D。

## 2. 再讲底层：程序是怎么做到的

### 2.1 底层原理一句话

程序从冻结的 30 层场景建立持久节点，每帧按时间轴给少量局部层采样旋转和透明度；第一次触摸只解锁一个循环环境风声源，并在宽高余量不足 2px 时做像素对齐的根节点缩放。

### 2.2 调用链

| 顺序 | 谁调用谁 | 传入什么 | 做了什么 | 输出或状态变化 |
|---|---|---|---|---|
| 1 | `OutdoorGateCScene.start` → `mountFromManifest` | V7 handoff manifest 和 SpriteFrame 路径 | 校验 manifest、按 `render_order` 加载 30 层并建立持久场景 | `mountState` 从 `loading` 变为 `mounted`，失败则释放资源并变为 `failed` |
| 2 | 场景 → `computeOutdoorGateCPixelAlignedViewport` | 设备宽高 | 保留 `SHOW_ALL`；只处理不足 2px 的近似余量 | 430×932 内容落在 y=1..930，上下各一行安全色 |
| 3 | `OutdoorGateCRig` → `sampleOutdoorGateCTimeline` | `elapsedMs`、`reducedMotion` | 对六个风通道、呼吸、云、星和花计算非累积采样值 | 局部节点围绕冻结姿态变化；5 秒后风归零 |
| 4 | `OutdoorGateCAudioGate.handleTouch` → `startAvailableAudio` | 首次 `TOUCH_START` | 解锁音频并启动已加载的环境风 | 一个循环 `AudioSource` 从 0 在 0.35 秒内渐入到 0.2 |
| 5 | `EVENT_HIDE/EVENT_SHOW` → 音频暂停/恢复 | 前后台事件 | 停止渐入、暂停或恢复已解锁声音 | 浏览器模拟恢复时仍保持单实例，不叠播 |

### 2.3 改动前后对比

- 改动前：视觉、音频和适配证据分散；430×932 外缘混色；风链只靠更轻的旧参数。
- 改动后：唯一候选绑定源码、构建、64 项哈希证据、真实音频和适配截图；外缘与环境风子项关闭。
- 真正发生变化的那一步：Wind A 只改六段风的峰值/旋转和 overlay 上限；适配只处理亚 2px 余量；音频在首触门控后播放。

### 4.1 核心技术

#### 纯时间轴与正常倍率验收分离

- 先用白话说它是什么：程序正确与观众看得见是两个问题，需要两套证据。
- 本次具体怎么用：纯函数证明六段顺序、归零和减动；独立 QA 再看无标注、原尺寸、正常速度 MP4。
- 为什么这样用：差分图会放大人眼在真实尺寸下看不到的变化，单靠它会产生假通过。
- 这样做的好处：机器能精确定位错误，人能守住真实体验。
- 它的限制或代价：最终仍需要独立真人样本，开发者自看不能替代统计阈值。
- 相关文件：`cocos-project/assets/scripts/cocos/outdoor-gate-c/outdoor-gate-c-timeline.ts`、`docs/GATE-C-HUMAN-TEST-KIT-V1.md`。
- 证据：Wind A 的顺序、ROI 和性能均成立，但独立 QA 仍将 GC-06 判为 `FAIL / P1`。

#### 首触门控的单实例环境风

- 先用白话说它是什么：声音先准备好，但用户没碰屏幕前不播放；触碰后只启动一个声源并柔和渐入。
- 本次具体怎么用：`playOnAwake=false`，首触设置 `unlocked`；0.35 秒 smoothstep 渐入；隐藏时暂停、显示时按状态恢复。
- 为什么这样用：既符合首触前静默合同，也避免恢复后叠播或突然满音量。
- 这样做的好处：静音仍能看懂，打开声音时更自然，状态可被浏览器复验。
- 它的限制或代价：浏览器模拟不能替代微信真机的锁屏、来电和音频抢占；音乐素材也尚未分配。
- 相关文件：`cocos-project/assets/scripts/cocos/outdoor-gate-c/outdoor-gate-c-audio-gate.ts`。
- 证据：独立 QA 将环境风子项判为 PASS，但 GC-09 整体仍为 BLOCKED。

### 4.2 基础或顺带用到的知识

- **资源生命周期**：异步加载先按批次收集结果，失败或销毁时释放 SpriteFrame、Effect 和 AudioClip，避免残留节点与声源。
- **哈希清单**：证据目录用 SHA-256 将候选身份和 64 个文件固定在一起，防止把旧构建或并发产物混入。
- **安全色 letterbox**：`SHOW_ALL` 保持完整构图，极小余量用 `#06265F` 填充，防止黑边和亚像素混色。
- **减少动态**：开启后时间轴直接输出零 transform/overlay，保留 V7 中性静态态。

### 4.3 想过但没有采用的技术

- **原 Wind B 全景增强**：未采用。草坡已经可读，继续加强草与全局 overlay 会增加焦躁并偏离失败点。
- **粒子、Shader、镜头摇动或骨骼形变**：未采用。它们增加性能和样式漂移风险，当前问题只在四个小局部的阶段可读性。
- **自动把 B-lite 写入构建**：未采用。它是用户可见样式变化，必须先获用户批准。

## 6. 为什么这样实现

- 最关键的实现选择：只动获得批准的 Wind A 参数，把视觉、音频、适配和证据绑定为唯一候选。
- 为什么当前方案够用：它足以验证引擎分层、时间轴、首触音频和多尺寸工程能力。
- 为什么没有必要做得更复杂：问题集中在小局部可读性，新粒子、Shader 或镜头不会更精准。
- 什么情况下当前方案会不够用：B-lite 与保守版都无法同时通过可读性和舒适度时，需要回到角色局部资产分层设计，而不是继续加数值。
