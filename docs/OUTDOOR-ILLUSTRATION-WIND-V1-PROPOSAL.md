# OUTDOOR-ILLUSTRATION-WIND-V1 提案

> 日期：2026-08-27  
> 负责人：主任务窗口  
> 状态：`APPROVED V1-A / STORYBOARD NEXT / NO BUILD / NO UPLOAD`  
> 归档说明：批准后仅做合同归一化——风页固定为 `140ms smoothstep`，并删除未单独批准的门光／室内时长；未扩展获批视觉范围。  
> 触发原因：用户在手机观看后明确判定 `OUTDOOR-MOTION-PHONE-V2-B`“完全看不出来”，并提出可改为“每次换一幅插画”。

## 1. 结论先行

停止继续放大 V2-B 的局部旋转。新的目标不是“让工程数值更大”，而是让手机原速、无标注观看时也能直接看出一阵风从草坡传到人物和猫。

负责人推荐 **A「五幅风页」**：上方星空、小屋与门保持一张稳定底图，只把下方草坡＋人物＋猫画成五幅连续完整插画并换帧。这样风的变化清楚，但不会让整片星空像相机在晃。

用户已批准 A「五幅风页」。下一步先制作五帧故事板与转场预览；故事板通过后再接 Cocos 本地候选。当前仍不得进入微信包或上传。

## 2. 保持不变

- 继续使用获批 V7 的 `390×844` 构图、普通深蓝星空、唯一一条淡银河、成年人背影＋普通家猫、小屋右侧中景、稳定门光和两朵弱光花。
- 继续使用水粉纸绘／染色纸层语言；不改角色体态、颜色、材质、房屋位置、地平线或室内 UI。
- 门从第一帧可点，插画换帧期间也不能阻塞进屋。
- 首触前数字静音；首触后沿用已批准环境风。音乐仍未批准。
- V7 与本次衍生插画都只允许用于可丢弃体验验证；正式入包仍须原创、可编辑、可追溯重绘。

## 3. A「五幅风页」——负责人推荐

### 3.1 画面拆分

- 稳定上景：约画面上方 `64%–68%`，包含星空、银河、远山、小屋和门；五帧间像素位置完全一致，不缩放、不平移、不调色。
- 换帧下景：约画面下方 `32%–36%`，每一帧都是一幅完整的“草坡＋人物＋猫”插画，不再用发梢、衣角、耳尖等小碎片旋转冒充主体变化。
- 两区用 `24–36px` 不规则草缘重叠遮住接缝；人物坐骨点、猫后腿落点、地平线和门热区在五帧中固定。

### 3.2 五帧故事板

| 帧 | 画面状态 | 必须清楚看见的变化 | 建议停留 |
|---|---|---|---:|
| F0 | 风前安静 | 草、人物衣摆、猫尾为中性姿态 | `0.8–1.0s` |
| F1 | 风先到远草 | 远草整体沿既有方向形成明显斜面；近草、人物、猫暂不动 | `0.50–0.65s` |
| F2 | 风到近草 | 前景草轮廓明显换形并压低，远草开始回落；人物仍有重量 | `0.55–0.70s` |
| F3 | 风经过人物 | 发梢与衣角形成新的完整轮廓，肩背不漂移、不变形；猫仍稍后 | `0.60–0.75s` |
| F4 | 风到猫并收住 | 猫耳角度和尾巴弧线明确改变，草保留余势，随后回到 F0 | `0.70–0.90s` |

帧间固定使用 `140ms smoothstep` 的双 Sprite 短交叉淡化，避免硬闪，也避免长重影。完整风页约 `3.5–4.2s`；首次进入稳定约 `0.8s` 后播放一次，之后每次安静 `4.5–6.5s` 再出现，不连续抖动。用户首触空闲时立即从 F0 开始；进行中不叠加，点门永远立即中断并进屋。

用户追加批准“每个跳转要有流畅的转场”。因此户外→室内、室内纸笺、设置、收尾和分享预览也不得出现黑屏、白闪、空帧或硬切；但这些跳转的具体画法、时长和声音链必须分别形成可见方案并向用户汇报，本次批准不自动授权新的门光、镜头、遮罩或额外特效。

### 3.3 可感知停止线

- 在 `390×844` 真机原速和 `25%` 缩略图中，F0、F2、F4 单独并排时，不看标注也能分出至少三种不同风态。
- 变化来自完整轮廓换形，不使用整屏摇晃、相机抖动、银河位移、亮度脉冲、动态模糊、粒子雨或 Bloom。
- 人物和猫仍“坐在同一地点看天空”，不能读成起身、受惊、瞬移或互相看。

### 3.4 减少动态等价态

开启“减少动态”后停止自动换帧，固定使用一幅中性但带轻微风向倾斜的静态插画；触碰反馈只允许一次 `≤180ms` 的亮度交叉淡化，不能用位置、旋转、缩放或连续闪动。即使完全静止，也能从草叶、衣角和尾巴的统一倾向理解“这里有风”。

### 3.5 资源与工程预估

- 推荐将五幅下景做成同尺寸 SpriteFrame／图集，由一条 SpriteFrame 动画轨换帧；Cocos Creator 3.8 原生支持在 Animation Clip 中给 `cc.Sprite.spriteFrame` 添加关键帧。
- 五幅下景先按独立透明 PNG 做可丢弃验证，再评估图集与微信真机 ASTC＋PNG 后备；压缩格式必须真机验证，开发者工具不能代替 ASTC 真机结果。
- 不把五张全屏图同时常驻；上景只保存一份，降低解码内存、包体和整屏 overdraw。

## 4. B「三幅整页」——备选，不推荐

使用三张完整 `390×844` 插画：安静、阵风峰值、风后。每张整体交叉淡化 `160–200ms`。

优点：最容易一眼看出变化，工程接入最简单。  
缺点：重复存储星空与小屋；任何绘制细差都会让银河、门和山线闪跳；整屏淡化更像幻灯片，也更容易破坏安静感。只有 A 的下景接缝无法稳定消除时才回退到 B。

  <https://developer.apple.com/design/human-interface-guidelines/motion>

  <https://www.w3.org/WAI/WCAG21/Techniques/css/C39.html>
