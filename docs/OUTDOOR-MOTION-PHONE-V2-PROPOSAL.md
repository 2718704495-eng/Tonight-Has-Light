# OUTDOOR-MOTION-PHONE-V2 真分层微风提案

> 日期：2026-08-27  
> 负责人：主任务窗口  
> 当前状态：`V1-A PHONE VISUAL FAIL / P1 / V2 BLOCKED AWAITING USER APPROVAL / NO SOURCE CHANGE / NO BUILD / NO UPLOAD`  
> 触发证据：用户在微信 `0.4.5` 真机体验后反馈“动态效果还是不太明显”

## 1. 结论与根因

`0.4.5` 的 Cocos 时间轴和六个风通道确实在运行；问题不是微信小游戏不能播放动画，而是当前画面组织方式让运动在手机上很难被读出来：

- 完整的人物、猫和草仍烘焙在全屏 `scene_clean_plate` 中。
- 六个可动节点只是覆盖在静态原像素上的透明局部副本，中性透明度为 `0`，峰值透明度仅 `0.30–0.40`。
- 人物发梢、衣角、猫耳和尾尖在 390×844 下的代表性峰值位移约为 `2.87px / 0.30px / 2.31px / 1.53px`；静态原像素始终留在原处，所以手机上更像很淡的双边或重影，而不是主体真的被风吹动。
- V1-A 一阵约四秒，之后有 `8–14s` 安静间隔；即使机器差分能捕获变化，用户仍容易错过。
- 既有 36 秒证据明确没有宣称真人视觉通过；其全屏最小 SSIM 仍约 `0.969`，平均 PSNR 最低约 `42.46dB`，说明变化集中在很小的局部。用户真机反馈优先于这些机械指标，因此 V1-A 手机可感知度判定为 `FAIL / P1`。

另有一项首触缺口：当前首触若正好落在自动开场风期间，会被“已有风链”拒绝而不保证补上一条完整风链；旧证据特意在开场风结束后触碰，没有覆盖真实的立即首触。

## 2. 研究结论

- Cocos 2D 节点可以围绕锚点独立旋转；因此应让真正的内容层运动，而不是用半透明副本模拟运动。  
  <https://docs.cocos.com/creator/3.8/api/en/class/UITransform>
- Cocos 的 2D 批处理建议减少不必要的材质、纹理和遮罩切换；本方案复用一张底图和现有六个局部节点，不引入全屏 Shader、Mask、Bloom 或粒子。  
  <https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/engine/ui-batch.html>
- Apple 的 Motion 指南强调让运动服务于层级和因果，并尊重“减少动态”；W3C 同样要求非必要交互动效可被关闭。  
  <https://developer.apple.com/design/human-interface-guidelines/motion>  
  <https://www.w3.org/WAI/WCAG22/Techniques/css/C39>

本项目不需要让整幅画面摇晃。正确方向是保持夜空、银河、小屋、地平线和镜头稳定，只让草、人物衣发和猫耳尾形成一次清楚而轻柔的风链。

## 3. 保持不变项

两个候选方案都必须保持：

- V7 的成年人背影＋普通家猫、构图、材质、配色、单条淡银河、十颗主星、小屋、稳定门光、两朵弱光花及室内暖屋和全部 UI。
- 风的因果顺序：远草→近草→人物发梢／衣角→猫耳／尾尖；所有水平方向一致。
- 银河、房屋、地平线、相机和整屏 transform 恒为 `0`；不新增粒子、Bloom、动态模糊、3D 灯光、提示、按钮或任务语义。
- 首触前数字静音；首触后环境风先响应。音乐方向仍未批准，不借本次修复接入。
- 减少动态时六个风通道、人物／猫呼吸、云位移和视差 transform 全为 `0`，只允许≤`180ms`、亮度增量≤`0.04` 的静态等价反馈。
- 本轮仍是可丢弃体验候选；V7 及其派生层不会因此成为正式生产资产。

## 4. A／B 方案

### A：参数增强叠层

保留“静态底图＋半透明局部副本”，只增加旋转、透明度和出现频率。

| 通道 | 开始／峰值／结束 | 峰值角度 | 透明度上限 |
|---|---:|---:|---:|
| 远草 | `0 / 800 / 2500ms` | `-2.8°` | `0.40` |
| 近草 | `300 / 1250 / 2800ms` | `-4.6°` | `0.44` |
| 人物发梢 | `1150 / 1850 / 3000ms` | `-5.0°` | `0.48` |
| 人物衣角 | `1350 / 2150 / 3250ms` | `-5.6°` | `0.48` |
| 猫耳 | `2350 / 2900 / 3500ms` | `-5.8°` | `0.50` |
| 猫尾尖 | `2550 / 3250 / 4050ms` | `-8.2°` | `0.50` |

优点：实现快，运行成本基本不变。  
风险：静态原像素仍留在底图里，角度越大越容易出现双边、闪动和透明重影；仍可能发生“数值更大，但手机上不像真的在动”。不推荐。

### B：真分层微风（负责人推荐）

制作一张 `motion-ready clean plate`：只还原六个可动区域背后的背景；远草、近草、人物发梢／衣角、猫耳／尾尖改为常驻、不透明、同源的真实内容层。中性合成必须与获批 V7 对位，动起来时原位置不再留一份静态副本。

| 通道 | 开始／峰值／结束 | 峰值角度 | 390×844 最远点几何位移 |
|---|---:|---:|---:|
| 远草 | `0 / 800 / 2500ms` | `-2.6°` | 约 `8.47px` |
| 近草 | `300 / 1250 / 2800ms` | `-4.2°` | 约 `13.97px` |
| 人物发梢 | `1150 / 1850 / 3000ms` | `-4.6°` | 约 `4.56px` |
| 人物衣角 | `1350 / 2150 / 3250ms` | `-5.2°` | 约 `6.34px` |
| 猫耳 | `2350 / 2900 / 3500ms` | `-5.4°` | 约 `3.38px` |
| 猫尾尖 | `2550 / 3250 / 4050ms` | `-7.6°` | 约 `4.30px` |

六通道不附加平移、缩放、回弹或累积漂移。B 用比 A 更小的角度即可被看见，因为移动的是主体本身。代价是需要重新整理六个局部及其背后底色；主要风险是透明边、接缝和中性态偏色，必须通过像素对位和真机检查拦截。

## 5. B 的锁定节奏

- 场景稳定约 `900ms` 后开始第一阵零操作微风。
- 首触时环境风按现有约 `350ms` 柔和渐入；当前空闲时，同帧启动视觉风。首触后 `160ms`，远草强度至少达到 `0.18`，在 B 中约等于 `1.5px` 可见位移。
- 若首触时已有一条刚开始的完整风链，不叠加、不跳帧；若剩余可见运动已低于 `1px`，当前风收束后至多 `250ms` 启动一条完整链。不得先消费首触标志再拒绝视觉风。
- 第一条风结束后安静 `4.5–6.5s`；之后每次安静 `6–9s`，完整起点间隔约 `8.5–13.1s`。快速滑动只复用当前风链，不叠加强风。
- 人物呼吸上限 `0.8%`（肩背约 `1.24px`），猫呼吸上限 `0.9%`（胸背约 `0.80px`），首次峰值至少错开 `800ms`；脚、坐骨保持固定。
- 十颗主星结构不变，仅沿用四颗低频微亮，增量≤`0.06`；两朵花上限仍为 `0.05 / 0.04`；云仍只保留既有 `0.8 / 1.6px` 慢移；门 transform 恒为 `0`、亮度峰峰值≤`2%`。

## 6. 性能与工程边界

- 只允许“替换一张底图＋复用六个局部节点”；禁止同时常驻两张全屏底图，禁止新建全屏透明层、Mask、Shader、逐帧对象或大面积 overdraw。
- 六个 ROI 合计约占 390×844 画布的 `11%`，中高端仍须保持平均 `55–60fps`，低端稳定不低于 `30fps`；输入 P95≤`100ms`，不得出现 >`250ms` 交互冻结。
- 中性态必须与 V7 对位；六个 ROI 外不得改变像素，ROI 内不得出现旧静态副本、透明裂缝、新笔触或明暗接缝。
- 360×800、390×844、430×932 和 430×844 压力态均须检查；20% OLED 亮度下仍能辨认风链。

## 7. 二元验收停止线

以下全部满足才允许称为本地候选通过；缺证据为 `BLOCKED`，出现反例为 `FAIL`：

1. 唯一候选、源码、资产清单、构建和证据哈希绑定；不得复用或冒充已上传 r8／`0.4.5`。
2. 中性态与 V7 对位，六个 ROI 外零新增差异；100% 与 25% 均无重影、透明裂缝或新笔触。
3. 30 秒 390×844 原速无标注视频覆盖开场、立即首触、至少两条后续风和安静间隙；不得用慢放、局部放大或调试标线作为真人刺激物。
4. 5 名未参与者真机无提示观看，至少 `4/5` 在三秒内自发说出草或画面在动，至少 `4/5` 能读出“草→人物→猫”；认为角色抖动、风太大或焦躁者不超过 `1/5`。
5. 至少 `4/5` 自发认为自然、凉快或舒服；用户本人若仍反馈“不明显”，直接 `FAIL`，不得用差分图或数值覆盖。
6. 立即首触必须获得声音反馈，并在 `160ms` 内进入可见风；已有风链不叠加，尾段首触至完整新链的等待≤`250ms`。
7. 减少动态逐帧检查所有 transform 精确为 `0`，静音与减动态均可理解场景和门入口。
8. 四尺寸无裁切、局部脱离或接缝；中高端／低端帧率、输入、冻结和 10 分钟内存满足项目停止线。
