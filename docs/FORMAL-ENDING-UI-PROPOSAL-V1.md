# 《今夜有灯》正式收尾 UI 提案 V1：灯下留笺 / 桌边暖纸

> 日期：2026-08-25  
> 版本：`FORMAL-ENDING-UI-V1`  
> Gate：B2 可见 UI 设计  
> 状态：`APPROVED A / B FOR 120% LARGE TEXT / LOCAL COCOS INTEGRATION AUTHORIZED`  
> 上游决定：`FORMAL-UI-V1.2-A / 灯一直为你亮着`、`INDOOR-N01-PROTOTYPE-V1 / 壶盖轻响`  
> 批准边界：用户已批准 A 为默认、B 为 120% 大字等价态；允许接入本地 Cocos 主流程，不自动授权微信构建、上传、提审或发布。

## 1. 现状问题

室内主流程的无界面动作合同已经具备：请求收尾、继续停留、结束今晚、固定分享、分享失败恢复与返回户外都可以执行。现在缺的是玩家真正看得见、并且不破坏暖屋的收尾界面。

已批准暖屋中，人物、猫、晚饭与窗外夜空几乎占满下半屏。直接套用大弹窗或底部结算卡，会盖住最能表达“有人留灯和晚饭”的内容；把房间压暗来衬按钮，则直接违背用户批准的“整屋明亮、角落不能黑”。因此本轮只比较两种低密度承载方式，不修改角色、构图、材质、配色或光线。

## 2. 查阅依据与本项目转译

- Apple HIG 建议把临时选择保持简短、少量、意图明确；按钮文案应描述结果而不是使用模糊的“确定”。本项目只保留两个当下选择，并沿用已锁定的结果式文案。[Action sheets](https://developer.apple.com/design/human-interface-guidelines/action-sheets)、[Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)
- Apple 的设计原则强调用户应能轻松退出、撤回或继续探索。本项目让“再坐一会儿”和“今晚到这里”等权，不把离开或分享做成奖励式主 CTA。[Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)
- WCAG 2.2 要求正文通常达到 `4.5:1`，有意义的控件边界/状态达到 `3:1`。项目继续采用比 WCAG 2.5.8 更严格的 `44×44px` 触控停止线，相邻热区至少 `8px`。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[Non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 减少动态不能只是把动画冻结在中间帧。本项目的收尾只允许不超过 `200ms` 的透明度或明度交叉；位移、缩放、弹跳与视差全部为 `0`。

本地 UI 设计库返回的“深紫色 CTA＋营销卡片”不符合本项目的暖纸水粉语言，已排除，不进入 A/B。

## 3. 两案共同合同

### 3.1 不可改变项

- 房间从始至终保持整屋明亮暖光，不加黑幕、暗角、毛玻璃遮罩、聚光或奖励闪光。
- 人物、普通家猫、晚饭、水壶、窗外星空及 `FORMAL-UI-V1.2-A` 的构图与色光不变。
- 参考 PNG 只用于隔离的浏览器设计板，不因本提案进入 Cocos 或微信包。
- 不新增姓名、关系、头像、留言、进度、连续天数、奖励或医疗/助眠承诺。
- 所有动作使用文字，不使用 emoji 或难以理解的图标。

### 3.2 文案与动作

收尾状态：

```text
水热了。你也先缓一会儿。
再坐一会儿
今晚到这里
```

完成摘要：

```text
这一夜，先放在这里。
给朋友留一盏灯
回到夜风里
```

分享预览：

```text
有人给你留了一盏灯
发给朋友
先不分享
```

分享失败：

```text
这次没有发出去。
再试一次
留在今晚
```

禁止新增 `回房间`，因为它不在当前动作合同中，也会让“完成后仍在暖屋 / 返回夜风”的空间关系变得含糊。禁止词包括：`完成`、`通关`、`奖励`、`领取`、`打卡`、`分享得`。

两项选择视觉等权；任何一项都不发光、不脉冲、不自动倒计时。分享只在完成摘要之后出现，不阻塞离开。

## 4. A 案：灯下留笺（负责人推荐默认）

### 4.1 画面

在 `390×844` 画面的暖色墙面右侧放一张中等窄幅、轻量的暖纸留笺，约占画面 `16%–19%`。它避开人物头肩、猫、晚饭、水壶和窗外银河；允许覆盖墙上的次要墙饰与少量桌边背景，但不改动底图本身。

- 暖纸：低饱和米杏色，纸纹与已批准水粉/染色纸语言一致。
- 文字：深褐墨色；正文最多两行。
- 两个动作：纵向排列，每个可见高度约 `48–52px`、实际热区至少 `52×44px`，间距至少 `10px`。
- 边界：细茶褐描边与极轻内阴影，只用于把纸面和暖墙分开；不使用黑色投影或发光描边。

### 4.2 优点与风险

优点：人物、猫、饭桌与窗外仍完整可见，收尾更像房间里有人留下的一句话，而不是应用结算页。

风险：可用宽度较窄，`120%` 大字时会过度换行。因此大字模式自动使用 B 的宽版承载，不把字体 SHRINK 回去。

## 5. B 案：桌边暖纸（备选 / 大字等价态）

### 5.1 画面

在底部安全区上方放一张横向暖纸托盘，宽约 `342px`、高约 `190–230px`。正文和两个动作可上下排列；不覆盖人物与猫的脸/头部，但会遮住部分地板、桌脚或坐垫。

- 纸面与 A 使用相同色票、字体、描边与触感，不能变成系统 Sheet、玻璃面板或营销卡。
- 两个动作纵向排列，`120%` 大字不缩小字体；必要时增加高度并上移，但底部不得落入手势区。
- B 可作为用户主动选择的默认方案，也可仅作为 A 的大字等价态。

### 5.2 优点与风险

优点：文字和热区最清楚，360/390/430 以及大字 120% 更容易稳定适配。

风险：遮住更多暖屋生活细节，画面更接近常见底部面板，沉浸感弱于 A。

## 6. 动效与状态

- 默认：纸面与文字在 `160–180ms` 内只做透明度显现；不从屏幕外滑入，不上弹，不缩放。
- 按下：`80–120ms` 明度变化；异步分享请求期间立即锁定重复触发，但不显示旋转加载器遮挡画面。
- 减少动态：所有 transform 为 `0`；仅允许 `≤160ms` 的明度/透明度交叉。
- 再坐一会儿：收尾纸面淡出，回到同一明亮暖屋安全节点；之后仍可再次请求收尾。
- 今晚到这里：同一纸面原位换成完成摘要，不切黑、不播放奖励动画。
- 分享失败/取消：回到可恢复的小状态，不丢进度、不惩罚、不自动重试。

## 7. 适配与二元验收

- 必须提供 `360×800`、`390×844`、`430×932`，并抽查 `430×844` 压力尺寸；不能整图横向拉伸。
- 微信顶部胶囊和底部手势区模拟覆盖下，不裁文字、不遮动作、不移动人物/猫/饭桌。
- 正文最终合成像素对比度 `≥4.5:1`，控件边界/状态 `≥3:1`。
- 触控区 `≥44×44px`，相邻边缘 `≥8px`；大字为真实 `120%`，禁止 SHRINK。
- A 默认、A 完成摘要、B 默认、B 完成摘要、分享预览、分享失败、大字 120%、减少动态静态态均有截图证据。
- 5 名未参与设计者看 `25%` 缩略图：至少 4 人仍先读到“明亮暖家/人物与猫/晚饭”，0 人把它说成任务结算、领奖或营销分享页。
- 连点结束或分享不得重复完成、重复请求或让迟到回调覆盖当前状态。

## 8. 样式影响说明

| 类别 | 本轮拟改 | 保持不变 | 风险/成本 |
|---|---|---|---|
| 角色 | 无 | 成年人背影＋普通家猫 | 无新增原创风险 |
| 构图 | 叠加临时收尾承载 | 暖屋底图不变 | A 遮次要墙饰；B 遮少量地板/桌脚 |
| 材质 | 暖纸 UI | 水粉纸绘暖屋 | 需正式分层时人工重绘纸纹与九宫格 |
| 配色/光线 | 仅 UI 色票 | 整屋明亮、无黑角 | 需实测暖纸与暖墙边界对比 |
| 标志性动效 | 160–180ms 淡显 | 壶盖/杯子时序 | 性能成本很低，无粒子/Bloom |
| Gate | 新增 B2 可见 UI 决策 | Cocos/微信停止线不变 | 用户批准后才进入实现 |
