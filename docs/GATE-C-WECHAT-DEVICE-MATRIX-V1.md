# Gate C 微信真机验收矩阵 V1

> 日期：2026-08-24  
> 候选：`gate-c-v7-20260824-41b0b7b1-wind-blite-audio-v1`  
> 当前状态：`BLOCKED`。本地微信包或开发者工具不能替代真实扫码、OLED/LCD、物理内存、音频路由与生命周期证据。  
> 样式边界：只验证已批准 V7＋B-lite，不得借测试修改角色、构图、材质、配色、夜空、光线或动效数值。

## 1. 判定规则

- `PASS`：指定设备、轮次、原始证据齐全且全部满足硬阈值。
- `FAIL`：有效证据明确违反任一硬阈值；不能用其他设备平均值冲掉。
- `BLOCKED`：缺真实 AppID/二维码、设备、批准音乐、诊断字段或原始证据。
- 任一必测单元 `FAIL`，设备子 Gate 为 `FAIL`；没有 `FAIL` 但存在 `BLOCKED`，总体仍为 `BLOCKED`。

## 2. 最小设备组合

| ID | 设备角色 | 屏幕与亮度 | 主要责任 |
|---|---|---|---|
| A1 | 仍受当前微信支持的低档 Android，3–4GB RAM、60Hz | LCD，60%；自动亮度/护眼关闭 | 低端 FPS、输入、LCD、后台/锁屏、内存与 soak |
| A2 | 主流 Android，6–8GB RAM | OLED，20%；自动亮度/护眼关闭 | OLED 黑位、音频焦点、耳机/外放、性能与 soak |
| I1 | 较旧但仍受支持的 iPhone | 面板类型如实记录；关闭原彩/夜览 | iOS 扫码、安全区、静音键、耳机/外放、锁屏/来电、性能 |

430×932 精确像素由开发者工具合成视口证明；真实胶囊、刘海和手势区由三台手机的 `safeArea` 证明。二者不能互相替代。

## 3. 每轮必须冻结的证据

- 候选 ID、微信包索引哈希、资源 manifest 哈希、环境风 OGG 哈希。
- AppID 只记内部代号或后四位；记录开发者工具、基础库、微信、系统版本。
- 设备 RAM、屏幕类型、逻辑宽高、DPR、刷新率和 `safeArea`。
- 亮度、媒体音量、自动亮度/护眼状态截图。
- 原始未剪辑视频、音频、console、performance trace、内存和诊断 JSON；标注版另存。
- 每台设备三次独立冷启动；原始证据最终生成 `HASHES.sha256`。

## 7. 缺陷停止线

- `P0`：候选/哈希不符；旧 H5 冒充真机；V7 未批准漂移；半场景/资源污染；证据身份不可追溯。立即停止，证据作废。
- `P1`：任一真机不满足视觉、音频、生命周期、安全区、性能、内存或资源硬线；首触前出声；恢复叠播。修复后重跑受影响设备。
- `P2`：单个已证明为采集工具故障的轮次，或不影响用户的证据元数据瑕疵。保留原始记录，不阻断已通过行为。

Cocos Creator 3.8 命令行退出码 `36` 是官方“构建成功”码，不是 P2；仍须同时保存 Finished 日志和产物证据。来源：[Cocos 命令行发布](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-in-command-line.html)。

## 8. 固定执行顺序

1. 冻结微信包和资源哈希。
2. 完成 DT-01…06。
3. A1/A2/I1 各三轮 PH-01 冷启。
4. 完成 OLED/LCD、安全区、减动。
5. 完成音频与生命周期。
6. 完成 FPS/输入、三轮 10 分钟内存和一轮 30 分钟 soak。
7. 汇总：有 `FAIL` 即设备子 Gate `FAIL`；仅缺证据则 `BLOCKED`；全部必测单元 `PASS` 才可关闭微信真机缺口。
