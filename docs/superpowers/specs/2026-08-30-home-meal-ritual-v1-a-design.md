# HOME-MEAL-RITUAL-V1-A 设计规格

> 日期：2026-08-30  
> Gate：A／回家支线故事、逐页交互与后续应用流  
> 状态：`GATE A APPROVED / WRITTEN SPEC USER APPROVED / GATE B PRODUCTION PLAN WRITTEN / H1 PILOT BLOCKED UNTIL USER APPROVAL / NO COCOS / NO BUILD / NO WECHAT / NO GIT`

## 1. 用户决定与体验目标

用户明确批准：

> `批准 HOME-MEAL-RITUAL-V1-A：放下外衣→厨房做饭→饭桌吃饭和温水→回到暖家全景`

本段不是待办清单或烹饪小游戏，而是一段短小、可停留、可跳过局部动作的回家生活叙事。它负责把户外的“清凉、安静、舒心”转换为室内的“灯一直亮着、屋子完整明亮、饭菜热起来、可以慢慢坐下”。

第一版继续只有匿名成年人和普通家猫，不增加家人、派对、对白、关系说明、任务、奖励或疗效承诺。

## 2. 当前方案与被否决方案

### 当前方案：五幅完整回家仪式

保留 `scene_01_home_shot_001..005` 五个稳定页面 ID，但用本规格替换旧 001–004 的“猫看门→起身→走坡→跨门”故事职责。点击草坡暖门本身已经表达离开草坡；随后通过冷暖匹配转场进入第一幅门内全景。

五幅顺序固定为：

```text
H1 门内归家全景
  → H2 放下外衣近景
  → H3 厨房完成简单热食
  → H4 饭桌近景：吃一点／喝口温水
  → H5 回到同一机位的暖家全景
```

### 未采用

- 保留旧四幅户外走路后再追加室内页：需要七至九幅，节奏过长，并破坏每条支线恰好五幅的合同。
- 先显示已备好晚饭的 H5，再另开做饭小剧场：时间顺序倒置，削弱故事因果。
- 把做饭、吃饭、喝水做成必须依次完成的操作：会把“回家”变成新的工作任务。

## 3. 冻结项与替代项

### 冻结项

- H5 必须逐字节消费用户已批准的 `HOME-F5-WIDE-ROOM-V1-A-R1` 390×844 文件，SHA-256 `569a7b9b71d16d13ad311bdea9a29d6bc93a7dc68c99892faf8c416f38bc1c51`。
- H5 不重绘、不裁切、不调色、不补字、不烘焙按钮，也不得继续压暗底部门槛、地板和前景。
- B 夜漫画保持深靛／暖赭有限色、成熟干笔墨线、克制网点和纸纹；角色、猫、屋内物件共享同一印刷逻辑。
- 人物仍是匿名成年人体态、短发、长裤和平底鞋；猫仍是普通四足家猫。人物左、猫右的关系不镜像。
- 房间从第一帧就是稳定明亮的暖家；墙、顶、地、家具和角落均可读。禁止黑房亮灯表演、黑角、整屏橙滤镜、Bloom、群像或奖励光。
- 根页 R4、星空支线、两朵花、户外音频边界、收尾 UI 和用户数据边界均不由本规格修改。

### 替代项

- 旧 `scene_01_home_shot_001..004` 的户外看门、起身、走坡与跨门故事描述标记为 `SUPERSEDED`。
- 旧“进入室内第一帧时晚饭已经全部备好”被细化为：灯、餐桌、壶杯和家的秩序已经在等待；人物在 H3 完成一份简单热食，完整晚饭只在 H4/H5 成立。
- 历史“点壶盖立即完成第一夜”和“拖光到壶边”不得接管本段进度；旧壶盖样片继续是历史 prototype-only 证据。

## 5. H4 互动规则

### 5.1 热区与状态

- `吃一点` 和 `喝口温水` 是两个平等、独立、幂等的环境互动；实际触控区均不小于 `44×44px`，相邻边缘至少 `8px`。
- 页面状态只允许 `none`、`ate`、`sipped`、`both`，仅服务当前绘本页视觉恢复，不写入夜晚完成、奖励或解锁。
- 点食物：以 `≤180ms` 静态交叉淡化到 `ate` 状态——中央热菜分量轻微减少，筷子由桌面移到碗沿；不播放咀嚼画面。
- 点温水：以 `≤180ms` 静态交叉淡化到 `sipped` 状态——杯中水线略低，杯子向人物方向移动少许；不播放夸张喝水、吞咽或身体效果。
- `both` 使用同一张可复核静态结果：热菜分量减少、筷子在碗沿、水线略低、杯子靠近人物；不把筷子和杯子同时举起。
- 点空白：前进 H5。用户无需先触发任何一个互动；已触发的动作也不限制另一个动作。

### 5.2 文字语气

固定动作词为：

- `放下外衣`
- `吃一点`
- `喝口温水`

允许的一次性翻页提示为：`轻轻碰一下，故事会往前走。`

禁止：`完成做饭`、`领取晚餐`、`补充能量`、`暖胃`、`治愈`、`助眠`、`恢复疲劳`、`坚持一下`、`今日任务` 或任何评分／奖励语气。

## 6. 转场与节奏

- 草坡暖门→H1：预载 H1 后进行 `320ms ease-in-out` 冷夜／暖门匹配淡变；户外蓝色最后消失，室内暖墙先接住门光。不得出现黑帧、白闪、Loading 空帧或奖励式亮屏。
- H1→H2、H2→H3、H3→H4：双全幅页面 `260ms ease-in-out` 交叉淡变；镜头距离变化来自两张独立静态构图，不用运行时整屏缩放模拟拉近。
- H4→H5：`420ms ease-in-out` 交叉淡变。通过桌边、人物左／猫右和窗户位置的构图匹配，让它读成镜头回到原处，不移动或缩放已批准 H5。
- 同一触碰只触发一次翻页；转场中锁住重复输入，不堆积队列。门外和下一页资源必须先就绪，失败时保留当前完整页面并提供原位置重试。
- 减少动态：全部位移、缩放、视差和推进为 `0`；所有页面统一 `150ms` 透明度交叉淡变。H4 两个动作继续使用静态状态差。

## 7. 声音合同

- 用户点击暖门前仍遵守“首次触碰前静音”；进入本段时已经发生主动触碰，允许把户外风在约 `1.2s` 内降到室外远声，同时让安静室内底噪在约 `1.5s` 内渐入。
- H2 可有很轻的布料摩擦；H3 可有一次锅盖轻碰与盛菜声；H4 可有餐具轻碰和杯底轻触桌面的声音。
- 禁止咀嚼声、吞咽声、ASMR 夸张近录、任务成功音、奖励音和对白。
- 所有声音仍需正式来源、许可、资产批准和手机外放复听；本规格不批准任何具体音频文件。静音时依靠静态前后状态完整理解因果。

## 8. 应用流与进度边界

后续实现必须新增独立 `HomeArrivalStory`，不能把五幅直接塞进旧 `NightSession`：

```text
outdoor-ready
  → home-story-loading
  → home-arrival-story(page 1..5)
  → indoor-ready（H5 图像继续留在屏幕）
  → 用户确认 3/5/8 后才进入 night-session
```

- `REQUEST_ENTER_HOUSE` 只启动回家故事，不得直接 `LOAD_INDOOR_NIGHT`。
- 每次翻页使用显式、幂等的 `ADVANCE_HOME_STORY_PAGE`；H5 完整呈现后才允许一次 `HOME_STORY_COMPLETED`。
- H5 到 `indoor-ready` 是底层状态切换，画面保持同一已批准全景；不得再闪一次门或重新加载一张近似图。
- 3/5/8 的计时仍必须等用户明确确认后开始，回家故事浏览时间不计入会话。
- H1、H2、H3、H4、H5 各自是安全恢复点；中断时回到最近完整静态页，不补播旧声音、不自动触发互动。
- H4 的 `ate/sipped` 只属于当前 story instance；不得写入 `completedNightIds`、夜晚解锁或核心完成。
- 旧“点壶立即完成第一夜”与本故事冲突，正式接线时必须保持停用。它不能作为 `HOME_STORY_COMPLETED` 或 `NIGHT_COMPLETED` 的替代事件。

## 10. Gate B 与后续验收线

进入实现前至少满足：

1. H1–H5 390×844 中文分镜板能明确读出“进门全景→放衣→厨房→饭桌近景→回到同一全景”。
2. H1 与 H5 的门、挂钩、餐桌、窗和房间轴线一致；H1 外搭与 H2/H5 挂钩上的外搭是同一件，H2 内搭与 H5 人物针织衫一致。
3. H3 至少保留一个能回读 H1/H5 主屋的空间锚点；墙地材质、木作、暖光方向与主屋一致，不能读成另一间房。H3 做出的热菜、H4 端上的热菜和 H5 已批准桌面内容在品类、器皿和颜色上连续。
4. H4 两个动作在 390 与 120% 大字中可读但不形成任务卡；静音、减动均能理解。
5. 195×422 缩略图下五幅镜头差异清楚，且 H1/H5 仍能认出是同一房间机位。
6. 360×800、390×844、430×932 和 430×844 压力态无裁字、关键物遮挡或热区漂移；安全边继续使用 `#06265F`。
7. H5 与批准文件逐像素一致；任何复合状态都不得修改底图。
8. Gate B 每页均具有来源、哈希和独立审查；用户逐页批准前不得交给 Cocos。
