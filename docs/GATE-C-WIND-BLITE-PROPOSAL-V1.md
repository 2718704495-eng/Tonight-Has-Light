# Gate C 风链 B-lite 提案 V1

> 日期：2026-08-24  
> 状态：`APPROVED FOR ONE GATE C CANDIDATE`  
> 批准记录：用户于 2026-08-24 在主任务明确回复“批准 B-lite V1”  
> 批准范围：只实施第 3 节推荐表，解决 Wind A 候选中人物局部与猫耳/尾尖在正常倍率下不够可读的问题；第 4 节保守备选仍为 `BLOCKED`  
> 唯一候选 ID：`gate-c-v7-20260824-41b0b7b1-wind-blite-audio-v1`

## 1. 为什么 A 仍未通过

独立 QA 对 `gate-c-v7-20260824-41b0b7b1-wind-a-audio-v1` 的 GC-06 判定为 `FAIL / P1`：远草与近草已经可读，但人物发梢/衣角仅能看到轻微变化，猫耳/尾尖在无标注、原尺寸、正常速度下仍难稳定裸眼辨认。

当前四个局部层只有约 `71×47`、`98×52`、`41×32`、`36×25px`。Wind A 的理论最远点位移约为 `1.49 / 2.44 / 0.88 / 1.59px`，且局部峰值相互重叠，容易被看成一次同步轻抖。调试数值、差分图和峰值放大只能说明代码在运行，不能证明观众看得见。

原方案 B 不作为推荐：草坡已经通过，继续同时放大草与全局风层会增加焦躁和“整张图在动”的风险，却没有精准解决小局部可读性。

## 2. 研究结论与边界

- Apple Motion 建议动效有明确目的、支持体验而不压过内容，并为不希望体验动态的人提供替代路径：<https://developer.apple.com/design/human-interface-guidelines/motion>
- W3C WCAG 2.3.3 要求非必要的交互动效能够关闭，并建议尊重系统减少动态偏好：<https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions>
- Cocos Creator 3.8 的 Tween 可以对旋转、缩放、颜色等属性做可控插值；本项目继续使用可逐帧采样的现有时间轴，不引入新粒子、Shader 或镜头系统：<https://docs.cocos.com/creator/3.8/manual/en/tween/>

这些官方资料只提供“有目的、可关闭、可控”的原则，不规定本项目的具体角度、透明度或时间。下列数值是依据本轮失败证据形成的工程假设，最终必须由正常倍率真人观察验证。

## 3. 推荐方案：两段式局部响应

核心不是让整场风更大，而是把四个小局部重新组织成两个可读阶段：“人物响应”与“猫响应”。

| 局部 | 开始 | 峰值 | 结束 | 旋转峰值 | 局部 overlay 上限 |
|---|---:|---:|---:|---:|---:|
| 人物发梢 | 2200ms | 2750ms | 3450ms | `-2.5°` | `0.28` |
| 人物衣角 | 2350ms | 2920ms | 3600ms | `-3.0°` | `0.28` |
| 猫耳 | 3300ms | 3750ms | 4300ms | `-3.0°` | `0.32` |
| 猫尾尖 | 3450ms | 3970ms | 4750ms | `-4.8°` | `0.32` |

- 人物两处峰值只相差 170ms，组合成较有重量的一次响应。
- 猫两处峰值相差 220ms，组合成更轻、更短的一次响应。
- 人物与猫阶段中心相隔约 1 秒，目标是让观众读出“人后、猫最后”，而不是逐帧数出四个部件。
- 理论最远点位移约提高到 `2.48 / 3.66 / 1.88 / 2.72px`。
- 不增加位移、缩放、网格形变、反向回弹、新资产、新节点或新 Shader，避免发梢脱离头部、耳朵像变大、尾巴变成角色表演。

远草与近草完整保留已通过的 Wind A：

| 局部 | 开始 | 峰值 | 结束 | 旋转峰值 | overlay 上限 |
|---|---:|---:|---:|---:|---:|
| 远草 | 700ms | 1450ms | 3100ms | `-1.5°` | `0.22` |
| 近草 | 1200ms | 2050ms | 3350ms | `-2.5°` | `0.22` |

## 4. 保守备选

本备选未随 B-lite V1 推荐版一起获批。只有推荐版出现局部重影、发梢脱离或至少 2/5 人认为角色在抖时，才可另行请求批准；不得在两案之间临时混值。

| 局部 | 旋转峰值 | 局部 overlay 上限 |
|---|---:|---:|
| 人物发梢 | `-2.1°` | `0.26` |
| 人物衣角 | `-2.6°` | `0.26` |
| 猫耳 | `-2.3°` | `0.29` |
| 猫尾尖 | `-4.0°` | `0.29` |

开始、峰值与结束时间与推荐版相同。该版本重影风险较低，但再次不可读的概率更高，因此不是默认推荐。

## 5. 明确保持不变

- 不改人物、猫、构图、材质、配色、银河、主星、小屋、门、道路、两朵花、云、呼吸、镜头和音频。
- 不修改远草、近草与其 `0.22` overlay。
- 不增加第二阵风、镜头晃动、视差、粒子、Bloom、动态模糊、全局亮度或新音效。
- t=0、t≥5s、tail 与 reduced-motion 必须继续与 V7 全像素零差。
- 减少动态时四个角色局部的旋转与 overlay 全为 0，不把动作缩短成另一种动态。
- 没有新资产和节点，预期性能成本接近零；主要风险是局部重影和“角色在表演”的观感，需要真人停止线约束。

## 6. 二元停止线

机器合同与真人体验分别判定；机器通过不能代替真人通过。

机器必须全部满足：

- 四个角色通道精确符合获批表格，方向一致；4750ms 后回落，5000ms 全部归零。
- t=0、t≥5s、tail、reduced 与 V7 全像素零差。
- 对比 Wind A，同一时间点的新增差异只能位于四个角色局部层外扩 8px 的 ROI；天空、银河、草、门和花新增差异为 0。
- 不新增 Sprite、资产、Shader 或调度器；console/page/network error 为 0。
- 390×844 原始样片为 9.6–10.0 秒、正常速度；首秒后 P95 帧时不超过 33.3ms，超过 100ms 长帧为 0。
- reduced-motion 中全部相关 transform 与 overlay 为 0。

真人必须全部满足：

- 5 名未参与实现的人看无标签、原尺寸、正常速度 MP4，至少 4/5 自发复述“草先动、人物随后、猫最后”。
- 至少 4/5 明确看出猫在人物之后响应；至少 3/5 在开放题中自行提到猫耳或尾巴。
- 至少 4/5 认为是“凉风、舒服或自然”；认为“角色在抖、风太大或焦躁”的人数少于 2/5。
- 认为局部重影、发梢脱离或耳尾像表演的人数不超过 1/5。
- 推荐版未同时达到可读性与舒适度时不得标 PASS；保守版也失败时停止继续放大，返回角色分层设计。
