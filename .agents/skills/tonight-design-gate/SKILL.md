# 今夜有灯设计门禁

把“用户最新决定”翻译成可以检查的需求、画面、动效、代码与证据链。这个 Skill 不代替美术创作；它负责阻止团队沿着旧版本或未经批准的画面继续实现。

## 必读顺序

1. 读取项目根 `AGENTS.md`。
2. 读取 `docs/PROJECT-MEMORY.md`。
3. 读取 `references/current-contract.md`。
4. 仅按当前任务需要读取角色、场景、资产、Cocos 或 QA 文档。

若上述内容与用户最新明确决定冲突，先记录差异并以用户最新决定为准；不得悄悄把旧方案当成当前方案。

## 工作流

### 1. 判定当前 Gate

- 需求、范围、用户旅程或文案：Gate A。
- 静态母版、角色同框、色彩、材质、受光或分层资产：Gate B。
- 8–10 秒 Cocos 真实动态样片：Gate C。
- 完整交互、场景流、存档接线或五夜扩展：Gate D。
- 视觉盲测、触控、适配、性能、生命周期或真机：Gate E。

不能跨 Gate 假完成。尤其禁止用自动测试、占位图或 Graphics 临时画面替代 Gate B/C 的可见证据。

### 2. 建立追踪表

使用 `references/traceability-template.md`，为每项工作填写当前需求、被替代要求、静态证据、动效证据、代码消费者、QA 证据、状态和负责人。

状态只使用：

- `ALIGNED`：各层已指向同一当前要求，但尚未验收。
- `DRIFT`：至少一层仍实现旧版或不同解释。
- `BLOCKED`：缺批准稿、资产、决策、设备或可复查证据。
- `PASS`：该 Gate 的明确验收线和证据都满足。
- `FAIL`：已有证据表明不满足验收线。

### 3. 执行当前 Gate

#### Gate B：可见设计

- 先做一张 390×844 静态母版，再谈批量资产或动画。
- 使用真实中文、最终角色轮廓、场景比例、光线层级和暗部，不用占位圆形或通用卡通人。
- 检查角色与场景共享材质、颗粒、边缘和同一冷暖受光。
- 生成图只能作为构图或光色参考，不能成为正式角色、Logo、文字、图标或关键互动物。
- 母版未由主任务和用户确认时，输出 `BLOCKED`，不得把开发标为可进入。

#### Gate C：动态样片

- 使用 Cocos 的持久节点、Prefab、Sprite、Atlas 和事件驱动时间轴；状态变化不能销毁重建整屏。
- 只做能验证情绪的 8–10 秒：风向传递、角色异步呼吸、主星错峰、花光、门的非催促状态，以及减少动态等价态。
- 动效必须从静态母版派生，不得在代码中重新设计角色或构图。
- 用真实 390×844 运行截图或短录屏验证，不能只交代码说明。

#### Gate D：正式实现

- 户外场景和室内夜晚进度分离；可选赏景互动不得改变夜晚完成状态。
- 进入室内时只触发一次幂等场景流事件。
- 保留声音、减动、大字、触控等价路径和安全节点恢复。
- 先实现一个完整竖切片并验收，再复制模板扩展内容。

#### Gate E：验收

- 重视觉状态必须有截图或录屏；Canvas/WebGL 不能只靠 DOM 或类型检查。
- 至少覆盖 360、390、430 宽度，默认、静音、减少动态、大字、加载失败和前后台恢复。
- 把产品功能优先级与缺陷严重度分开；会把团队带入错误 Gate 的基线漂移属于 P0 缺陷。

### 4. 交付前自检

逐项回答：

1. 这次工作对应用户哪一条最新决定？
2. 是否仍引用了被替代的首屏、角色或视觉稿？
3. 用户能直接看到或操作的证据是什么？
4. 静音、减少动态、大字和低端设备是否仍能完成？
5. 当前状态是什么，为什么？
6. 下一 Gate 的进入条件是否真的满足？

结论必须先写状态，再写发现和下一步。若状态是 `DRIFT` 或 `BLOCKED`，停止后续量产或正式实现，把阻塞项交给主任务裁决。
